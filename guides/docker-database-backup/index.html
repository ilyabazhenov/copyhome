Бекап базы из Docker-контейнера: MySQL, MariaDB и PostgreSQL

Если база работает в Docker, дамп снимается её же утилитой внутри контейнера через docker exec. Ставить клиент базы на сам сервер не нужно.

Обновлено 18 октября 2026

Найдите контейнер

ssh deploy@example.com "docker ps --format '{{.Names}}\t{{.Image}}'"

Команда покажет имена запущенных контейнеров и их образы, например shop-db mysql:8.4 или crm-db postgres:16. Пользователь на сервере должен входить в группу docker, иначе команды придётся запускать через sudo.

PostgreSQL

В официальном образе postgres подключение изнутри контейнера обычно не требует пароля:

ssh deploy@example.com "set -o pipefail; docker exec crm-db pg_dump -U postgres crm | gzip" \
  > pgsql-crm-$(date +%F).sql.gz

Вместо postgres укажите пользователя из переменной POSTGRES_USER, если вы её задавали.

MySQL и MariaDB

Пароль root уже лежит в переменной окружения контейнера, поэтому его не нужно копировать в команду. Из-за кавычек команду удобнее положить в скрипт на сервере, например ~/dump-shop.sh:

#!/bin/bash
set -euo pipefail
docker exec shop-db sh -c 'exec mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" \
  --single-transaction --routines --triggers --events shop' | gzip

Сделайте его исполняемым (chmod 700 ~/dump-shop.sh) и запускайте с Mac:

ssh deploy@example.com ./dump-shop.sh > mysql-shop-$(date +%F).sql.gz

В образах MariaDB 11 утилита называется mariadb-dump, а пароль лежит в $MARIADB_ROOT_PASSWORD. Учтите, что пароль, переданный через -p, виден в списке процессов на сервере, пока идёт дамп. Если у сервера есть другие пользователи, передавайте пароль через временный файл с опциями.

Без -t

Не добавляйте к docker exec флаг -t. С терминалом Docker меняет переводы строк, и дамп портится. В docker compose по той же причине нужен -T:

docker compose exec -T db pg_dump -U postgres crm | gzip > crm.sql.gz

Почему не копировать том с данными

Папка, в которой работающая база хранит файлы, всё время меняется. Её копия, снятая на ходу, может не запуститься или запуститься с повреждёнными таблицами. Дамп — это согласованный снимок, и восстанавливается он в базе любой совместимой версии. Файлы, которые приложение хранит в других томах, например загрузки пользователей, можно забирать обычным архивом, как в инструкции «Бекап сайта на свой компьютер».

Проверьте результат

У MySQL в последней строке дампа стоит -- Dump completed on …, а у PostgreSQL -- PostgreSQL database dump complete:

gunzip -c mysql-shop-2026-10-18.sql.gz | tail -n 1
gunzip -c pgsql-crm-2026-10-18.sql.gz | tail -n 8 | grep "dump complete"

Пусть бекапы делаются сами

В CopyHome контейнер выбирается из списка, а дамп снимается через docker exec на сервере или прямо на этом Mac. Пароль не попадает в командную строку, MariaDB 11 с mariadb-dump тоже подходит, каждый дамп проверяется до последней строки, а копия уходит в Яндекс Диск, Google Диск, S3 или на NAS.
