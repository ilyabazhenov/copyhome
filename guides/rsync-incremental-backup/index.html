Инкрементальный бекап папок через rsync: снимки и хранение по календарю

Архивировать 20 ГБ загрузок каждую ночь долго и дорого по месту. rsync скачивает только изменившиеся файлы, а жёсткие ссылки превращают каждый запуск в полный снимок папки.

Обновлено 18 октября 2026

Простая синхронизация

rsync -rlpt deploy@example.com:/var/www/uploads/ ~/Backups/uploads/current/

-rlpt копирует папки, символические ссылки, права и время изменения. Это -a без владельца и группы: на Mac файлы всё равно будут принадлежать вам. Слеш в конце пути источника значит «содержимое папки», без него на Mac появится вложенная папка uploads. На сервере нужен только сам rsync: sudo apt install rsync.

У такой копии одна проблема: она всегда одна. Если файл на сервере испортили или удалили, следующий запуск перенесёт порчу и в копию.

Снимки с жёсткими ссылками

Каждый запуск создаёт новую папку с датой. Файлы, которые не изменились с прошлого снимка, не скачиваются, а становятся жёсткими ссылками на него:

b=~/Backups/uploads
d=$(date +%F)
rsync -rlpt --exclude='cache/' --link-dest="$b/latest" \
  deploy@example.com:/var/www/uploads/ "$b/$d/" \
  && ln -sfn "$b/$d" "$b/latest"
  • Каждая папка выглядит как полная копия, её можно открыть в Finder или скопировать целиком.
  • Место занимают только новые и изменённые файлы. du -sh ~/Backups/uploads/* это покажет.
  • Старый снимок можно удалить, и новые от этого не пострадают: файл исчезает с диска, только когда на него не осталось ни одной ссылки.
  • latest переключается, только если rsync закончил без ошибок, поэтому оборванный запуск не станет основой для следующего.

При первом запуске latest ещё нет. rsync предупредит об этом и скачает всё целиком.

Сколько снимков хранить

Простое правило «последние N»:

cd ~/Backups/uploads && ls -1d 20*/ | sort -r | tail -n +15 | xargs rm -rf

Оно оставляет 14 свежих снимков. Но такой скрипт не смотрит, удачными ли были последние запуски, и при череде сбоев сотрёт хорошие копии.

Удобнее хранить копии по календарю (схема GFS): последнюю копию каждого из 7 последних дней, каждой из 4 последних недель и каждого из 12 последних месяцев. Это не больше 23 снимков, а история уходит на год назад. Поздно замеченную ошибку можно откатить на неделю или на месяц.

А как же облако

Жёсткие ссылки работают только на одном диске. Облачные хранилища их не понимают, поэтому туда снимок лучше отправлять одним архивом:

tar -C ~/Backups/uploads/2026-10-18 -cf - . | zstd -T0 > uploads-2026-10-18.tar.zst

Пусть бекапы делаются сами

В CopyHome это режим «Только изменения (rsync)»: каждый снимок выглядит полной папкой, неизменившиеся файлы — жёсткие ссылки, а в облако снимок уходит архивом tar.zst. Хранить можно последние N копий или копии по календарю, по умолчанию 7 дней, 4 недели и 12 месяцев. Неудачные копии не считаются, и пока нет хорошей полной копии, ничего не удаляется.
