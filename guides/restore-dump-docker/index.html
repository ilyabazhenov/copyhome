Как проверить бекап базы: восстановить дамп в Docker на Mac

Бекап, из которого вы ни разу не восстанавливались, — это надежда, а не бекап. Проверить его проще всего во временной базе в Docker на своём Mac, не трогая рабочий сервер.

Обновлено 18 октября 2026

Что понадобится

Docker Desktop или OrbStack на Mac и файл дампа, например mysql-shop.sql.gz. Если дамп сжат zstd, поставьте его через Homebrew: brew install zstd, и вместо gunzip -c используйте zstd -dc.

MySQL и MariaDB

Запустите временный сервер. Возьмите ту же основную версию, что на рабочем сервере, или новее:

docker run -d --name restore-test -e MYSQL_ROOT_PASSWORD=test mysql:8.4
until docker exec restore-test mysqladmin ping -h 127.0.0.1 -uroot -ptest --silent; do sleep 2; done

Вторая строка ждёт, пока сервер в контейнере допишет первоначальную настройку и начнёт принимать подключения.

Создайте базу и загрузите дамп:

docker exec restore-test mysql -uroot -ptest -e 'CREATE DATABASE shop'
gunzip -c mysql-shop.sql.gz | docker exec -i restore-test mysql -uroot -ptest shop

Флаг -i здесь нужен: через него дамп попадает в контейнер. Если загрузка падает на строках с DEFINER=`shop`@`localhost`, уберите их на лету:

gunzip -c mysql-shop.sql.gz | sed -E 's/DEFINER=`[^`]+`@`[^`]+`//g' \
  | docker exec -i restore-test mysql -uroot -ptest shop

PostgreSQL

docker run -d --name pg-test -e POSTGRES_PASSWORD=test postgres:16
until docker exec pg-test pg_isready -h 127.0.0.1 -U postgres -q; do sleep 1; done
docker exec pg-test createdb -U postgres crm
gunzip -c pgsql-crm.sql.gz | docker exec -i pg-test psql -X -q -1 -v ON_ERROR_STOP=1 -U postgres -d crm

Версия образа должна быть не старее pg_dump, которым снят дамп. Если загрузка останавливается на role "crm" does not exist, создайте роль (docker exec pg-test createuser -U postgres crm) или снимайте дамп с --no-owner --no-privileges.

Сверьте таблицы

Число таблиц в дампе:

gunzip -c mysql-shop.sql.gz | grep -c '^CREATE TABLE'

И в восстановленной базе:

docker exec restore-test mysql -uroot -ptest -N -e \
  "select count(*) from information_schema.tables where table_schema='shop' and table_type='BASE TABLE'"
docker exec pg-test psql -U postgres -d crm -Atc \
  "select count(*) from information_schema.tables where table_schema not in ('pg_catalog','information_schema') and table_type='BASE TABLE'"

Числа должны совпасть. Дальше можно открыть пару важных таблиц и посмотреть последние записи: заказы, пользователей, публикации.

Уберите за собой

docker rm -f restore-test pg-test

Контейнеры удаляются вместе с данными, на Mac остаётся только сам дамп.

Почему не на сервере

Восстановление поверх рабочей базы в случае ошибки затрёт живые данные. Проверку бекапа лучше делать там, где ошибиться не страшно. Возвращать базу на сервер стоит только после такой проверки и вручную.

Пусть бекапы делаются сами

CopyHome делает это сам: «Восстановить» загружает дамп в базу в Docker или по адресу на этом Mac, убирает DEFINER и строки про владельцев и сверяет число таблиц. Если включить пробное восстановление, раз в неделю свежий дамп загружается во временную базу и она удаляется после проверки. На сервер CopyHome ничего не заливает.
