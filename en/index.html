How it works

Three steps to peace of mind

  1. 01

    Add a server

    Host and user, sign in with a key or a password. Your ~/.ssh/config and ssh-agent just work. "Check SSH" shows whether the server has everything needed.

  2. 02

    Pick what to keep

    MySQL databases and folders, with exclusions like cache/ or node_modules. Each source can be backed up on its own.

  3. 03

    Set a schedule

    How many copies to keep and whether to send one to the cloud. From there CopyHome does the rest and tells you if anything is off.

What happens during a backup

    

    
The dump streams straight into a file on your Mac and never lands on the server's disk. The MySQL login and password go through stdin, so they never show up in ps.

Security

      
Your server keys stay with you

    

    

      
macOS Keychain
MySQL and SSH passwords and cloud tokens are encrypted with a key from your Keychain. They are never stored in plain text.

      
System ssh
No home-made protocol code. Your keys, your config, your agent. A changed host key blocks the connection.

      
Invisible in ps
The database password reaches the server through stdin, not command arguments, so other users on the server can't see it.

      
OAuth with PKCE
You sign in to the cloud on Yandex's page. No app secret is needed or kept in the code.

    

  







  

    

      
FAQ

      
The short answers

    

    

      

        Do I need to install anything on the server?
        
No. It only needs bash, gzip, tar and mysqldump, which are almost always there already. If no database password is set, CopyHome uses ~/.my.cnf on the server.

      

      

        Where are backups stored on the Mac?
        
In ~/Backups/fast-backup/<Project>/<date-time>/ as plain .sql.gz, .sql.zst and .tar.gz files that open without CopyHome. No proprietary formats.

      

      

        What if the window is closed?
        
CopyHome stays in the menu bar and keeps running on schedule. Turn on "Open at login" and the window won't even appear.

      

      

        What about a huge database?
        
The dump runs with --single-transaction, so InnoDB tables aren't locked, and zstd or pigz compression uses every core on the server. Large log tables can be saved as structure only.

      

      

        Is PostgreSQL supported?
        
Not yet. PostgreSQL is next on the roadmap, along with incremental folder backups via rsync and one-click restore.
